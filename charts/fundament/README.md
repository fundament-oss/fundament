# fundament chart

Deploys the whole platform. `values.yaml` holds the defaults and documents every value;
each environment adds one file on top.

## Values files

| File | Used by |
|---|---|
| `values.yaml` | every deploy |
| `values-local.yaml` | local development: the `env-local` Skaffold profile behind `just dev` |
| `values-hotreload.yaml` | `just dev-hotreload` (`hotreload` profile): startup probes for Air-driven services |
| `values-gardener-local.yaml` | the `local-gardener` Skaffold profile; generated by `just cluster-worker gardener-connect`, not in git |
| `values-sandbox.yaml` | PR preview environments, see `docs/developer/fundament/preview-environments.md` |
| `values-production.yaml` | the `env-production` Skaffold profile, which has no target cluster yet |

## Immediate cluster deletion

`clusterWorker.gardenerImmediateClusterDeletion` is off when unset. When on, deleting a
cluster does not wait for what runs inside it: Gardener removes blocking finalizers on the
first pass instead of after 5 minutes, or an hour for custom resources, and stops pods
without a grace period.

Those finalizers exist so workloads can clean up what they manage outside the cluster:
volumes on external storage, load balancers, DNS records. With the setting on, such
resources can be left behind. Turn it on only where nothing outside a cluster depends on
what runs inside it. The `local-gardener` Skaffold profile turns it on.

## CRDs

`crds/` holds `plugininstallations.plugins.fundament.io`. Helm installs files in `crds/`
on first install only and never upgrades or removes them. On shoots, cluster-worker
applies its own copy, see the Plugin machinery section of `cluster-worker/README.md`.
